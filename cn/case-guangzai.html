01 — 问题

一个「感觉坏掉了」的智能系统

光仔是由AI驱动的伙伴，它们在玩家的家园中生活、工作并产生各种需求。其行为由一套状态机控制——对玩家而言默认不可见。当光仔在任务中途停下、乱跑或倒地，玩家得不到任何解释。没有理解，便只会怀疑是bug，而非智能。信任就此崩塌。

规模让问题更加棘手：满员情况下，一名玩家需要同时管理多达20只光仔，每只都有独立的AI状态和优先级在运行。挑战不在于设计单个角色，而在于为整个系统建立可读性。

「AI行为本身是真实且正常运转的。设计的问题，是让玩家感受到这一点——而不是感到被它抛弃。」

// 家园内景——玩家与光仔伙伴。家具摆放影响光仔的需求与行为。
02 — 我的职责范围

逻辑与界面，两端全握

大多数UX设计师接手一个现有系统，只负责设计表层。而我同时负责两端。我定义了AI优先级层级——决定哪些状态优先响应、紧迫程度如何——再设计将这套规则实时传达给玩家的UX层。

这与所有AI产品面临的核心挑战直接对应：如何让自主系统的行为，对依赖它的人而言清晰可读、值得信任、可以行动？

AI逻辑

设计三级优先级体系，规定光仔状态的权重规则、哪些状态可覆盖其他状态，以及需求未被满足时系统如何逐级升级。

UX层

设计每个优先级在世界中的呈现方式——通过气泡、图标、动效和管理界面——让玩家一眼就能读懂系统状态。

03 — 优先级层级

三个等级，一套清晰的系统。

20只光仔同时运行，玩家不可能响应所有事件。这套层级确保关键状态绝对不会被忽视，而环境状态则可以安全忽略——玩家在不自觉中建立直觉，无需刻意学习。

04 — 光仔角色需求

让角色状态在世界中清晰可读

每只光仔都有三项核心需求——能量、食物和心情——会随时间逐渐消耗。我设计了每种状态在不同优先级下的世界内呈现方式。最棘手的问题：梦游和晕倒在视觉上相似，但需要完全不同的应对。一旦区分错误，整套信任体系将全面崩盘。

05 — 设施警报

当环境需要关注时

独立于角色需求，设施——卫生间、床铺、娱乐区——同样有自己的状态。我设计了一套专属的设施警报系统，让玩家能立即区分「是光仔有问题」还是「是设施有问题」。

L3 Alert
设施可用
若设施未被光仔占用，玩家可自行使用。玩家靠近时将显示完整操作选项。
L3 Alert
光仔需要设施
光仔无法使用该设施，玩家必须介入——清洁、升级或重新引导。

「角色警报与设施警报的分离是刻意为之——玩家需要知道的不只是出了问题，更要知道问题究竟出在哪里。」

06 — 状态界面与响应流程

从警报到理解，再到行动

世界中的气泡传递「有事发生」的信号，状态界面则告诉玩家具体是什么——并提供应对工具。我设计了完整流程：需求进度条、情境化操作菜单、喂食、空状态，以及操作后的反馈确认。

// 状态界面——三项需求进度条一目了然，操作菜单根据光仔当前状态动态适配
// 空状态——提示玩家先去烹饪，形成资源闭环
// 喂食后的反馈——由光仔个性驱动的对话，让交互充满意义
07 — 管理系统

完整的名单总览

玩家需要一个专属的总览界面，查看所有光仔的状态——谁在工作、谁需要关注、谁处于空闲——并根据每个角色的技能、个性和稀有度做出任务分配决策。

// 角色详情——支持有据可依的任务分配决策
